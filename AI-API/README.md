# 🧠 ColorMate — AI-API

**FastAPI microservice powering ColorMate's computer vision and deep learning features**

</div>

This service hosts the three core AI models behind ColorMate: object detection (YOLO), fruit/vegetable freshness classification (MobileNetV3Large), and the clothing color-harmony evaluation engine. The ASP.NET Core backend (`Back-End/`) calls into this service over HTTP for every AI-powered feature.

---

## 📂 Folder Structure

```
AI-API/
├── main.py                              # FastAPI app entry point — registers all routers
├── requirements.txt                     # Python dependencies
├── models/                              # Trained model weights (committed to the repo)
│   ├── yolo26m.pt                       # YOLO object detection model
│   ├── final_model.keras                # MobileNetV3Large fruit/vegetable classifier
│   └── OutfitHarmony_HF_SafeRebuild_v1.pt  # Segmentation model used by the harmony engine
├── services/
│   ├── object_detection/
│   │   ├── service.py                   # Router: /object-detection/*
│   │   └── config.py                    # Model path, thresholds, host/port config
│   ├── fruit_vegetable_disease/
│   │   ├── router.py                    # Router: /fruit-vegetable-disease/*
│   │   └── model.py                     # Preprocessing + inference logic
│   └── clothing_color_harmony_evaluator/
│       ├── router.py                    # Router: /clothing-color-harmony/*
│       ├── service.py                   # ColorMateAPI wrapper class
│       └── model.py                     # Full v9 harmony-scoring engine (segmentation, color theory rules, recommendations)
└── temp/                                # Runtime scratch folder for uploaded outfit images (gitignored / not tracked)
```

> **Note:** the `temp/` folder is created automatically at runtime by the harmony evaluator to temporarily store uploaded images before analysis. It is not meant to be committed — if it doesn't exist, the app creates it on startup.

## 🚀 Getting Started

### Prerequisites
- Python 3.10+ (recommended; matches the TensorFlow/PyTorch versions pinned in `requirements.txt`)
- pip

### 1. Install dependencies

```bash
cd AI-API
pip install -r requirements.txt
```

> Model weight files (`yolo26m.pt`, `final_model.keras`, `OutfitHarmony_HF_SafeRebuild_v1.pt`) are already included under `models/` — no separate download step is needed.

### 2. Run the server

```bash
uvicorn main:app --reload
```

By default this serves on `http://127.0.0.1:8000`.

To expose it for the mobile app/backend to reach during development (as done in this project), tunnel it with a tool like **ngrok**:

```bash
ngrok http 8000
```

Then point the Back-End's `appsettings.json` (`ObjDetection:BaseUrl`, `FruitsClassification:BaseUrl`, `OutfitRating:BaseUrl`) at the generated tunnel URL.

### 3. Verify it's running

```bash
curl http://127.0.0.1:8000/
# {"message": "ColorMate AI API is running"}
```

Interactive API docs (Swagger UI, auto-generated by FastAPI) are available at:

```
http://127.0.0.1:8000/docs
```

## 🔌 API Reference

All routes are mounted with the prefixes registered in `main.py`.

### 🟦 Object Detection — `/object-detection`

| Endpoint | Method | Description |
|---|---|---|
| `/object-detection/` | `GET` | Health/status check |
| `/object-detection/health` | `GET` | Reports model status (`YOLOv8m (CPU)`) |
| `/object-detection/detect` | `POST` (multipart `file`) | Detects objects in a single image |
| `/object-detection/detect-batch` | `POST` (multipart `files[]`) | Detects objects across multiple images |

**Example response — `/detect`:**
```json
{
  "success": true,
  "objects": [
    {
      "object_id": 0,
      "class_name": "shirt",
      "confidence": 0.87,
      "bbox": [34, 56, 210, 340]
    }
  ],
  "total_objects": 1
}
```

Configuration (in `services/object_detection/config.py`):
- `MODEL_PATH`: `models/yolo26m.pt`
- `CONFIDENCE_THRESHOLD`: `0.3`
- `IOU_THRESHOLD`: `0.45`
- `CLASSES_TO_EXCLUDE`: `[0]` (excludes the `person` class so only objects/clothing are returned)
- Forced to run on **CPU** (`USE_GPU = False`)

---

### 🍎 Fruit & Vegetable Disease Detection — `/fruit-vegetable-disease`

| Endpoint | Method | Description |
|---|---|---|
| `/fruit-vegetable-disease/predict` | `POST` (multipart `file`) | Classifies an uploaded fruit/vegetable image as Healthy or Rotten |

**Example response:**
```json
{
  "success": true,
  "prediction": {
    "predicted_class": "Healthy",
    "confidence": 0.94,
    "probabilities": {
      "Healthy": 0.94,
      "Rotten": 0.06
    }
  }
}
```

Model: fine-tuned **MobileNetV3Large** (`models/final_model.keras`), input resized to 224×224, preprocessed with `mobilenet_v3.preprocess_input`. Classification threshold is 0.5 on the "Rotten" probability.

---

### 👕 Clothing Color Harmony — `/clothing-color-harmony`

| Endpoint | Method | Description |
|---|---|---|
| `/clothing-color-harmony/analyze` | `POST` (multipart `file`) | Analyzes an outfit image and returns a harmony score + suggestions |
| `/clothing-color-harmony/health` | `GET` | Engine health/version check |

**Example response — `/analyze`:**
```json
{
  "score": 8.2,
  "suggestions": [
    "Great contrast between your top and bottom.",
    "Consider a neutral accessory to balance the palette."
  ]
}
```

This is powered by the **ColorMate Harmony Evaluator (v9 engine)** — a rule-based (no training required) pipeline that:
1. Segments clothing items from the image using a dedicated YOLO segmentation model (`OutfitHarmony_HF_SafeRebuild_v1.pt`)
2. Extracts dominant colors per garment and converts them into perceptual color space (LCh)
3. Scores hue harmony, contrast, and lightness balance using color-theory rules, weighted by garment area
4. Generates human-readable styling suggestions based on the computed score

## ⚠️ Notes & Gotchas

- **CPU-only inference**: both the YOLO object detector and the harmony engine's segmentation model are explicitly forced onto CPU (`model.to("cpu")`). If you have a working CUDA setup and want GPU acceleration, update `USE_GPU` / remove the `.to("cpu")` calls accordingly.
- **CORS** is currently wide open (`allow_origins=["*"]`) for development convenience — tighten this before any production deployment.
- The `temp/` directory used by the harmony evaluator grows with every analyzed image since uploaded files aren't automatically cleaned up — consider adding a cleanup job or switching to in-memory handling if disk usage becomes a concern.
